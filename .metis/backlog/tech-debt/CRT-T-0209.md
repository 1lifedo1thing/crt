# Eliminate ~10% idle CPU floor (redraws at idle with nothing animating)

## Objective **[REQUIRED]**

After the v0.1.4 perf branch (sleeping event loop), idle CPU dropped 91% → ~10% of a core, but a ~10% floor remains. Find who requests redraws at idle and eliminate them so an idle window costs ~0% CPU.

## Backlog Item Details

### Type
- [x] Tech Debt - Code improvement or refactoring

### Priority
- [x] P2 - Medium (nice to have)

### Technical Debt Impact
- **Current Problems**: An idle crt window burns ~10% of a core continuously (battery/fans).
- **Benefits of Fixing**: Near-zero idle CPU, matching other modern terminals.
- **Risk Assessment**: Low urgency; already 9x better than v0.1.3.

## Findings so far (2026-09-03, measured on the v0.1.4 branch)

Measured with release build, minimal config (`CRT_CONFIG_DIR` pointing at a config with just `[shell] program`), Apple Silicon macOS:

- Idle CPU ~10.3%. **Disabling cursor blink (`[cursor] blink = false`) changes nothing** — still ~10%. Blink is NOT the driver.
- Default theme has `crt: None`, no effects, no sprite — `is_animating()` should be false.
- `sample` profile (saved at `.metis/idle-profile-v0.1.4.txt`, symbolized): main thread is repeatedly inside `window_event` (src/app/handler.rs:432, RedrawRequested) → `render_frame` (src/render/mod.rs:256) → `vello::Renderer::render_to_texture` → wgpu compute passes. **Full vello renders are happening at idle** — this is real GPU submission work, not just wakeups.
- So: redraw requests keep arriving with nothing animating. Open question is who requests them — candidates to check:
  - `render.dirty` being set every frame somewhere (e.g. by the 250ms macOS menu poll path in `about_to_wait`, or by `drain_ptys`/`process_pty_updates` marking content changed spuriously)
  - `effects_renderer.is_animating()` returning true via a stuck `needs_render` flag (crates/crt-renderer/src/effects/renderer.rs:187)
  - macOS itself delivering RedrawRequested (occlusion/compositor), with `render_frame` doing a full vello re-render instead of an early-out when nothing changed
- Related fix already landed on the branch: `CrtPipeline::is_animated()` now only reports animating when `flicker > 0.001` (the shader's only time-dependent term), so static CRT themes no longer pin 60fps. This didn't move the default-theme floor since default has crt disabled.

## Acceptance Criteria **[REQUIRED]**

- [ ] Identified and documented the source of idle RedrawRequested/dirty marking
- [ ] No visual regressions (visual test suite still green)
