# Background update check with toast, menu entry and [updates] config

## Parent Initiative

[[CRT-I-0034]] In-place self-update with update notifications. Phase 3: ships the notification on its own, for every install kind.

## Objective

CRT tells the user, inside the emulator, when a newer release exists (REQ-001, REQ-002, REQ-007, REQ-008), without blocking the UI (NFR-001) and without any network access when checks are disabled (NFR-006, NFR-007). Managed and dev installs get the right upgrade hint.

## Acceptance Criteria

- [ ] `crt-update::fetch::Fetch` trait (`fn get(&self, url, dest: Dest) -> Result<(), FetchError>` with `Dest::{Memory, File(path)}`) and a `CurlFetch` impl that runs `curl -fsSL --connect-timeout 5 --max-time <n> -A crt/<ver>` as a subprocess; missing `curl` is a distinct error with a message naming it. `MemoryFetch` in tests.
- [ ] `[updates]` in `config.rs`: `check: bool = true`, `interval_hours: u32 = 24`; documented in `assets/config.toml`.
- [ ] `~/.config/crt/state/update.toml` (`UpdateState { last_check, last_notified_version, last_finished_version }`), created on demand; unreadable/corrupt state is treated as empty with a warn log.
- [ ] After the first presented frame the app spawns one worker thread that fetches `SHA256SUMS` (only when `check` is on and `now - last_check >= interval`), parses it, classifies the install, and sends `UpdateEvent::{Available { version, kind }, UpToDate, Failed(err)}` over a channel, then wakes the loop with a new `WakeReason::Update`.
- [ ] On `Available`: info toast "CRT vX.Y.Z is available — Update from the menu" (self-replaceable kinds) or "… — installed via <manager>, run `<hint>`" (managed) or "… — rebuild from source" (dev), shown at most once per version per interval (`last_notified_version`); the update menu entry is retitled "Update to vX.Y.Z…" and stays until applied or the version changes.
- [ ] Menu: macOS native menu gets "Check for Updates…" under the app menu; Linux/Windows context menu gets the same item. "Check for Updates…" runs the check immediately regardless of `interval_hours` and shows "You're up to date (vX.Y.Z)" or the failure toast. With `check = false` the menu item still works (the user asked); the launch check never runs.
- [ ] Self-replaceable kinds: the retitled entry does nothing yet beyond a toast "In-place update coming in a later release; re-run the install script" until CRT-T-0214/0215 land (keep the wiring point obvious). Managed/dev kinds: the entry opens the release page with `open`.
- [ ] `crt --version` prints `crt 0.1.6 (<install kind>)`; exits before any window is created.
- [ ] Failure toasts per REQ-010 for offline / non-200 / parse error, each with a distinct message and a `warn` log; a failed check still updates `last_check` so an offline machine does not retry every launch.
- [ ] Tests: worker logic factored as `fn run_check(fetch: &dyn Fetch, state: &mut UpdateState, now, cfg, kind) -> Option<UpdateEvent>` and unit-tested with `MemoryFetch` for: newer / same / older version, interval not elapsed, `check = false`, fetch error, parse error, notified-once-per-version. Toast wording lives in one `fn` with a test per install kind.
- [ ] Manually verified on macOS: launch with a fake older `CARGO_PKG_VERSION` (env override for dev builds, `CRT_FAKE_VERSION`, debug builds only) and see the toast; `check = false` produces no `curl` process (check with `RUST_LOG=debug`).

## Implementation Notes

### Technical Approach
- Reuse the existing `Waker` (`src/app/mod.rs`) and add `WakeReason::Update`; drain the channel in `about_to_wait` next to the PTY drain.
- The worker owns its `CurlFetch`; the main thread never blocks on it. Kill the child on app exit via `Child::kill` in the worker's drop path if still running.
- `CRT_FAKE_VERSION` is compiled only under `debug_assertions`.

### Dependencies
CRT-T-0211 (the file exists on releases), CRT-T-0212 (manifest + classification).

### Risk Considerations
Nagging: the once-per-version-per-interval rule and the persistent-but-quiet menu entry are the whole anti-nag design; get the state transitions unit-tested rather than eyeballed.
