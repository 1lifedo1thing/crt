# First-launch finish: asset manifest refresh, .old cleanup, install.sh integration, docs

## Parent Initiative

[[CRT-I-0034]] In-place self-update with update notifications. Phase 6: everything `install.sh` does besides copying the binary, done by the binary itself on its first launch after an upgrade, with one implementation shared with the script.

## Objective

After an upgrade the config dir gets the new bundled themes, fonts and `default_config.toml` without losing the user's edits, Linux icons/`.desktop` are refreshed, the previous version is removed, and the whole thing is documented (REQ-006, REQ-011, REQ-012).

## Acceptance Criteria

- [ ] `crt-update::assets`: `fn refresh(bundled: &Path, config_dir: &Path, manifest: &mut AssetManifest) -> RefreshReport { written, skipped_modified, unchanged }`. For each bundled file: if absent → write and record hash; if present and its current hash equals the recorded hash → overwrite and record; if present and the hash differs (user edit) or there is no record (pre-manifest install) and the content differs → skip and list. `config.toml` is never in scope.
- [ ] Manifest at `~/.config/crt/state/assets.toml`: relative path → sha256, plus the version that wrote it. Missing manifest = first run: files identical to the bundled ones get recorded silently, differing ones are skipped (protects existing edits).
- [ ] Bundled assets are located per install kind: `crt.app/Contents/Resources/assets` for bundles; for the Linux binary, the tarball's `assets/` must be shipped alongside the binary (`~/.local/bin/../share/crt/assets` or embedded) — pick one and update `release.sh`/`install.sh` to match. Decision recorded in the task before implementation.
- [ ] First-launch hook: after the first presented frame, when `CARGO_PKG_VERSION != state.last_finished_version`: run `refresh`, refresh Linux icons + `.desktop` (same logic as `install.sh`'s `install_desktop_entry`), delete `crt.old` / `crt.app.old` if present, set `last_finished_version`. One info toast summarising ("Updated to v0.1.6. 3 bundled themes skipped because you edited them: dracula, matrix, tron").
- [ ] `crt update --finish-install <assets_dir>` runs the same refresh headlessly; `install.sh` calls it after copying the binary, falling back to its current copy logic only if the binary fails to run (so first installs of the first version with this feature still work). The unconditional theme overwrite in `install.sh` is removed.
- [ ] The vestigial `sudo xattr` in `install.sh` is replaced by a non-sudo `xattr -dr` that ignores failure (documented in a comment why).
- [ ] `docs/how-to/update.md`: how checks work and when, `[updates]` options, privacy note (one request to github.com, `curl` user agent), what "installed, takes effect next launch" means, what gets refreshed and how edited themes are protected, manual rollback for both layouts, package-manager installs.
- [ ] README install section links to the doc and mentions in-app updates.
- [ ] Tests: `refresh` over a temp config dir for every branch (absent / unchanged / user-modified / no-manifest identical / no-manifest differing / new file in a later version); the first-launch decision `fn should_finish(running, state) -> bool`; `.old` cleanup with and without the file; `.desktop` rendering compared to the script's output.
- [ ] Manual: upgrade a v0.1.5 install with an edited `dracula.css`; after the next launch the edit survives, new themes appear, `.old` is gone.

## Implementation Notes

### Technical Approach
- Hashing: `sha2` on file contents; manifest written atomically (`.tmp` + rename).
- Keep the report data-only; wording lives with the other update toasts.
- `install.sh` change is small: after `install_binary`, `"$bin" update --finish-install "$assets_dir" || setup_config_fallback`.

### Dependencies
CRT-T-0214 (state file, CLI subcommand plumbing). Runs after CRT-T-0215 in practice so the bundle layout is available for the asset-location rule.

### Risk Considerations
The "no manifest yet" first run is the delicate case: every existing install lands there. Skipping any file that differs from the bundled copy is the safe default even though it means a user who never edited anything but has a stale v0.1.3 theme keeps it; the toast tells them.
