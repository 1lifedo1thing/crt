# Publish SHA256SUMS with releases and use it in the AUR script

## Parent Initiative

[[CRT-I-0034]] In-place self-update with update notifications. Phase 1; no app change. Must ship with the next release so the updater has something to fetch.

## Objective

Every GitHub release carries a `SHA256SUMS` asset listing all four tarballs, and the AUR publish script reads its sums from that file instead of recomputing them. The updater's discovery (REQ-001) and integrity check (NFR-002) both depend on this file.

## Acceptance Criteria

## Acceptance Criteria

- [x] `.github/workflows/release.yml`: the `release` job (after `download-artifact`, before `action-gh-release`) writes `SHA256SUMS` in the artifacts dir with `sha256sum crt-*.tar.gz > SHA256SUMS` (coreutils format: `<hex>  <filename>`, two spaces, filename with no path) and adds it to `files:`.
- [x] `scripts/publish-aur.sh` downloads `SHA256SUMS` from the release and reads the x86_64 / aarch64 sums from it; recomputation removed. Fails clearly if the file or an entry is missing.
- [x] `scripts/release.sh` (local packaging) produces the same file for local tarballs so a dry run of the AUR script works offline.
- [x] Format is documented in a comment in `release.yml` as the contract the app parses: one line per asset, filenames `crt-<semver>-<os>-<arch>.tar.gz`, all the same version.
- [~] Verified on a real tag: `curl -fsSL https://github.com/colliery-io/crt/releases/latest/download/SHA256SUMS` returns the file and `sha256sum -c` passes against the downloaded tarballs.

## Implementation Notes

### Technical Approach
- `sha256sum` is available on `ubuntu-latest` (the release job runs there); no macOS variant needed in CI. `release.sh` runs locally on macOS, so use `shasum -a 256` there and normalise to the same two-space format.
- Keep the filename bare in the sums file: `(cd artifacts && sha256sum crt-*.tar.gz > SHA256SUMS)`.

### Dependencies
None. Blocks CRT-T-0213 (check) and CRT-T-0214/CRT-T-0215 (apply) in practice, since they fetch this file.

### Risk Considerations
The next release after this change is the first one the updater can see; older installs (≤ v0.1.5) never had a checker, so nothing is lost.
