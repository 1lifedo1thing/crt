# In-place apply for the Linux user binary and the crt update CLI

## Parent Initiative

[[CRT-I-0034]] In-place self-update with update notifications. Phase 4: the first self-replacing path, on the simpler layout (a single file), plus the headless CLI that scripts and the macOS task reuse.

## Objective

A `UserBinary` install (default `~/.local/bin/crt`) can replace itself from the menu or from `crt update`: download, verify, unpack, atomic swap, previous version kept as `crt.old`, every failure leaving the install untouched (REQ-004, REQ-005, REQ-009, REQ-010, REQ-012, NFR-003, NFR-004).

## Acceptance Criteria

- [ ] `crt-update::apply` module: `fn apply(plan: &UpdatePlan, fetch: &dyn Fetch, progress: &mut dyn FnMut(Stage)) -> Result<Applied, ApplyError>` where `UpdatePlan { kind: InstallKind, asset: Asset, staging_dir }` and `Stage::{Downloading, Verifying, Unpacking, Installing}`.
- [ ] Locking: `<staging>/lock` created with `create_new`, holding the pid; a live pid → `ApplyError::InProgress`; a dead pid → stale lock removed. Released on every exit path (RAII guard).
- [ ] Staging dir is `<install_dir>/.crt-update/`, created fresh; leftover staging dirs from a crashed run are removed at the start of the next apply and at app launch.
- [ ] Download to `<staging>/<asset name>` via `Fetch::get(.., Dest::File)`; sha256 (`sha2`) compared to the manifest before anything is unpacked; mismatch → `ApplyError::ChecksumMismatch { expected, actual }` and the file deleted.
- [ ] Unpack with `tar` + `flate2` into `<staging>/unpacked/`, rejecting entries with `..` or absolute paths; the Linux layout yields `crt` and `icons/`.
- [ ] Swap: `rename(current, current.with_extension("old"))` then `rename(staged_binary, current)`; on failure of the second rename, rename `.old` back and report `ApplyError::Swap`. Executable bit preserved. Staging dir removed afterwards.
- [ ] `Applied { version, previous: PathBuf }` reported; the app shows "vX.Y.Z installed. It takes effect the next time you open CRT." and resets the menu entry. No restart prompt.
- [ ] The menu entry from CRT-T-0213 now drives this for `UserBinary`; progress stages are shown as successive info toasts (rate-limited to one per stage).
- [ ] CLI: `crt update` prints the same stages to stdout, exits 0 on success / 2 when up to date / 1 on failure; `crt update --check` reports only. Uses the same lock. Works without a display.
- [ ] Every `ApplyError` variant maps to a specific toast/CLI message per REQ-010; permission denied names the path and points to the install script.
- [ ] Integration tests (crate-level, both CI platforms): a temp dir with a fake `crt` binary (a shell script that prints its version), a `MemoryFetch` serving a tarball built in the test and a matching `SHA256SUMS`; assert: success swaps and keeps `.old`; checksum mismatch leaves everything untouched; lock held by a live pid refuses; stale lock proceeds; a read-only install dir fails with `PermissionDenied` and no `.old`; a tarball with `../evil` is rejected; the "current" binary keeps running during the swap (spawn it sleeping, swap, confirm exit code).
- [ ] Manually verified on Linux (CI runner or VM): `install.sh` v0.1.5 install → `crt update` to a test release → new `--version`.

## Implementation Notes

### Technical Approach
- Progress: `curl` has no machine-readable progress on stdout; report stage transitions only (the tarballs are ~17 MB, a few seconds). Percentages are a later nicety.
- `Fetch::get` to a file must write to `<name>.part` and rename on completion so a partial download is never mistaken for a full one.
- Keep `apply` free of app types; the app maps `Stage`/`ApplyError` to toasts in one place.

### Dependencies
CRT-T-0213 (menu entry, state, `Fetch`). CRT-T-0215 reuses everything here except the layout-specific unpack/swap.

### Risk Considerations
The two-rename swap is only atomic on one filesystem; the staging dir being a sibling of the target guarantees that. Test the cross-device case (staging on tmpfs) fails cleanly rather than half-copying.
